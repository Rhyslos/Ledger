Lust Language Guide

Lust is a small, strict language for apps, games, tools and scripting. Checks are written as questions, states are built in and own their memory, and every file ends with end. This guide covers all of it, with an example for each part.

Use the search box at the top (press / or Ctrl+K) to find anything: a word like cMap, a piece like slider, or a question like "loop backwards". Every heading has its own link: point at it and click the hash sign beside it to copy where it is.

This guide follows Lust 2.0.0 alpha 73. The full rulebook is LUST.md in Lust's own folder; when the two ever differ, the rulebook wins. In Ledger, press Ctrl+Shift+P and type Docs to open this guide again.

The short version

state Mood = [Cheerful, Grumpy];

class Player {
    has {
        string name = "Hero";
        int hp = 20;
        Mood mood = Mood.Cheerful;
    }

    method hurt(int damage) {
        hp -= damage;

        is hp <= 0? then {
            print("{name} is knocked out!");
        } or is hp < 10? then {
            mood = Mood.Grumpy;
            print("{name} has {hp} hp left.");
        }
    }
}

Player ada = new Player { name = "Ada" };
ada:hurt(12);

end
  • Every statement ends with ; and every file ends with end.
  • No if: a check is a question, is hp < 10? then { … }, and or { … } is the "otherwise".
  • Types come first: int hp = 20;, method int doubleIt(int n) { … }.
  • . reads a field, : calls a method: ada.hp, ada:hurt(12).
  • Text shows values in { }: "{name} has {hp} hp".

Run it with lust run main.lst, or press F5 in Ledger.

Files and the basics

What every Lust file looks like, before anything else.

Kinds of file

Both kinds are the same language with the same rules. lust run runs either kind straight away through Lua, with nothing else to install. Only lust build needs Rust.

Statements, blocks and end

  • Every statement ends with ;: int lives = 3;, print("hi");.
  • Blocks are in { } and don't take a ; after the }: is ready? then { go(); }.
  • A few things that end in a { } but are still statements do take one: new hook { … }; and Player p = new Player { … };.
  • Every file ends with end on its last line. Only blank lines and comments may follow it.
  • Every project has a main.lst at its root. That's where the program starts, and the folder with it is the project's folder.

Comments

-- a comment, the Lua way
// also a comment
--[[ a block comment,
     over several lines ]]

Because -- starts a comment, subtracting a negative number needs a space: a - -b, not a--b.

The order inside a file

  1. Imports: fetch and get.
  2. States and nodes.
  3. Classes, objects, assemblies, schemas and methods.
  4. pass: what other files may use.
  5. The code that runs.
  6. end.
fetch "entities/player":Player;

state AppState = [Booting, Running];

method start() {
    Player hero = new Player { name = "Ada", hp = 100 };
    print("Ready: " + hero.name);
}

pass AppState;

start();

end

Naming

  • PascalCase for kinds of things: classes, objects, states, schemas, assemblies and nodes. Player, GameState, LootSpawner.
  • camelCase for everything else: variables, fields, methods, hooks, files and folders. currentHp, takeDamage(), entities/player.lst.
  • So Player player = new Player; reads clearly: the capital is the kind, the small letter is the thing.
  • No dashes in names, since - takes away: int max-hp is a mistake that suggests maxHp. Files and folders that other files fetch can't have dashes either: use myParts or my_parts.
  • No ALL_CAPS names: int MAX_HP suggests maxHp. For a value that never changes, use lock.
  • Lust's own words are reserved and can't be names: int loop = 3; says loop is one of Lust's own words, so it can't be a name. The list is under Reserved words.
  • Map keys are text, so any text is fine there: "max_hp", "item-id".

Types and variables

A variable is declared with its type, its name and a value, and keeps its type forever.

Variables

int lives = 3;
float speed = 1.5;
string name = "Ada";
bool alive = true;

lives = lives - 1;
name = "Bo";
  • A variable declared inside { } only exists inside those braces.
  • A name can't be declared twice while it still exists.
  • An int fits where a float goes. The other way needs .int(): int whole = speed.int();.
  • Lust never changes a type quietly: "1" == 1 is a mistake, and "hp: " + hp needs hp.text() (or "hp: {hp}").

lock: values that never change

lock int maxLives = 3;
maxLives = 4;          -- a mistake, caught before anything runs
main.lst:2:1  maxLives is locked, so it keeps the value it started with. To change it, leave out lock where it's declared.
  • Giving a locked variable a new value (=, +=, is) is a mistake.
  • A field can be locked too: has { lock int maxHp = 20; }. It gets its value when the thing is made (its starting value, or one given in new Player { maxHp = 30 }) and keeps it.
  • Locking a thing (lock Bag bag = new Bag;) means bag is always that same bag, but its fields can still change: bag.size += 4; is fine. The same goes for a locked array's or map's items.
  • A class's own state changes as it goes, so it can't be locked, and neither can a loop's counter.

Sized numbers

An int takes 64 bits. Where a smaller one will do, these take fewer in the program lust build makes: a uint8 array of a million tiles takes 1 MB instead of 8. They're completely optional; int works everywhere.

TypeHolds

int16-32768 to 32767
int32-2147483648 to 2147483647
uint80 to 255
uint160 to 65535
uint320 to 4294967295
  • Reading one gives an int, so maths, text and comparisons work as for any int.
  • Putting a number into one checks it fits. A number written out has to fit before anything runs (int8 x = 300; is a mistake). One worked out while running stops the program if it doesn't fit: 303 doesn't fit in a uint8, which holds 0 to 255. It never wraps round quietly.
  • They go in variables, fields, parameters, return types, arrays, maps, cMaps, hooks, saves and JSON. Not yet in components, events, database tables or native methods: use int there.

How big an int can be. A built program holds whole numbers up to 9223372036854775807. lust run runs through Lua, whose numbers are exact only up to 9007199254740991, so there a bigger one stops the program with a message instead of showing a wrong number. Build the program to use bigger ones.

nothing

nothing means "no thing here yet". Only class-typed values (and hooks and entities) can be nothing.

class Pet {
    has {
        string name = "Rex";
    }
}

Pet pet = nothing;
is pet === nothing? then {
    pet = new Pet;
}
print(pet.name);

Using a field or method on nothing stops the program with an error naming the line: this is nothing, so it has no fields or methods.

Questions and choices

Lust has no if. A check is a question: it starts with is and ends with ?.

is … ? then

int hp = 3;

is hp == 0? then {
    print("Out cold");
} or is hp < 5? then {
    print("Barely standing");
} or {
    print("Fine");
}
  • or is …? then { } asks the next question when the first was no.
  • or { } on its own runs when every question was no.
  • Writing if is a mistake that shows the Lust way: Lust asks questions instead of if: is hp == 0? then { }.

Asking about a bool

Ask a bool straight, rather than comparing it with true:

bool alive = true;

is alive? then { print("still here"); }
is not alive? then { print("gone"); }

not flips a bool anywhere: alive = not alive;.

Comparing

WriteMeans
a == bThe same: equal numbers, text or bools; the very same thing; for state options, the same option or one inside the other
a != bNot the same
a === bExactly the same: for state options, only that very option
a !== bNot exactly the same

a && b, a || bBoth, either. Group with ( )
  • For numbers, text and bools, === means the same as ==.
  • Things made from classes are compared by which thing they are: two new Heros with the same fields are two heroes, so == says false. Compare their fields to ask whether they're alike: a.name == b.name.
  • Comparing different types ("1" == 1) is a mistake caught before running.
  • A single & or | is for the bits of whole numbers, not for joining checks.

either: one of two values

int hp = 12;
string mood = either hp > 10? "happy" or "grumpy";
print("{either hp > 0? "alive" or "down"}");

check and when

check goes through a state's options, with one when block for each:

state Mood = [Calm, Busy, Angry];
Mood mood = Mood.Busy;

check mood {
    when Calm {
        print("relaxed");
    }
    when Busy, Angry {
        print("working");
    }
}
  • Every option is covered, always. There's no "anything else": leave an option out and Lust says which one is missing. So when a state gets a new option, Lust points at every check that needs a when for it.
  • One when can cover several options: when Busy, Angry { … }.
  • Write the option on its own, without the state's name: when Calm, not when Mood.Calm.
  • Options inside options: a when for an option covers the options inside it. Put the more particular one first: when ActiveGame.Combat { … } and then when ActiveGame { … } for the rest.
  • Bools work too, with when true { } and when false { }.
  • Numbers and text use questions instead, since there's no list of every value to cover.
  • Each when has its own { }, so one can never run on into the next.

Maths and text

Arithmetic

  • + - * / % work on int and float. ( ) groups.
  • int / int gives an int: 7 / 2 is 3. Use 7.float() / 2 for 3.5.
  • There's no power operator. Use Maths:power(2, 3). (2 ^ 3 is the bitwise xor, so it's 1.)
  • Below zero: int / int drops what's after the point, towards zero: -7 / 2 is -3. % takes the sign of the number on its left: -7 % 3 is -1. Built programs and lust run agree on all of these.
  • Dividing a float by zero gives infinity, -infinity or not a number; Maths:isFinite(x) asks. Dividing an int by zero stops the program.
  • Very big and very small numbers can be written with e: 1e30, 2.5e-7. They're always floats.

Changing a value using itself

int hp = 20;
hp -= 5;           -- hp = hp - 5
hp += 1;
hp *= 2;
hp /= 3;

string log = "";
log += "done. ";   -- += adds to text too

They work on variables, fields (player.hp += 5;) and items (scores[2] += 1;). += and -= move a vec3, *= and /= scale one, and *= turns a rotation. The bitwise ones (&=, |=, ^=, <<=, >>=) work the same way.

Bits: & | ^ ~ << >>

WriteMeansExample
a & bThe bits that are on in both12 & 10 is 8
a | bThe bits on in either12 | 10 is 14
a ^ bThe bits on in one but not the other12 ^ 10 is 6
~aEvery bit flipped~0 is -1

Handy for flags, several yes-or-no settings packed into one number:

lock int walk = 1;
lock int swim = 2;
lock int fly = 4;

int moves = walk | swim;
is moves & swim != 0? then {
    print("can swim");
}
moves |= fly;      -- now it can fly too
moves &= ~walk;    -- and no longer walk
  • They work on whole numbers only. On a bool, use &&, || or not; on a float, use .int() first.
  • The order is Rust's: ~, then * / %, then + -, then << >>, then &, ^, |, then comparisons, then && and ||. So moves & swim != 0 means (moves & swim) != 0.
  • Moving by 0 to 63 places works; anything else stops the program, and so does << pushing bits off the top.

Text

  • Text is in double quotes: "Ada". \n is a new line, \" a quote.
  • + joins text: "Hello, " + name. It never turns other values into text by itself, so hp + lives always adds numbers.
  • #name is how many letters.
  • Text has tools of its own, like name.upper() and line:split(","): see Text tools.

Values in text

Put a value in text by writing it in { }:

string name = "Ada";
int lives = 3;
float speed = 1.5;

print("Hello, {name}! You have {lives} lives.");
string card = "{name} has {lives} lives and moves at {speed}";
print("{lives + 1} next time, {either lives > 2? "plenty" or "careful"}");
  • Anything goes in the { }: a variable, a field, maths, a method call, even more text. Each value is shown the way print shows it, so there's no .text() to write.
  • A { straight before a name, a bracket, # or text starts a value. Any other { is just a brace, so JSON ("{\"name\": \"Ada\"}") and patterns ("[0-9]{4}") need nothing special.
  • For a plain { before a name, write \{: "\{lives} is written like this".

Vectors, rotations and colours

For games, 2D and 3D, and anything drawn. They're copied like numbers: vec3 b = a; makes a copy, so changing b.x doesn't change a.

vec3

vec3 pos = [0, 0, 1.5];
vec3 speed = [2, 0, 0];
float dt = 1.0 / 60;

pos = pos + speed * dt;
pos.z = 0;
print(pos);
print(pos:length(), pos:distance([0, 0, 0]));
  • Arithmetic: + and - between vec3s, * and / by a number, and -pos points the other way.
  • Parts: pos.x, pos.y and pos.z are floats that can be changed. Z is up.
  • Methods: length(), normalized() (the same direction, 1 long), dot(b), cross(b), distance(b), lerp(b, 0.25) (a quarter of the way to b) and angle(b) (degrees, 0 to 180).
  • Each number is a 32-bit float, about 7 digits, so compare with a little room: is a:distance(b) < 0.0001? then { … }.
  • Every step is worked out the same in a built program and in lust run, to the last bit.

rotation

A turn, written as degrees around x, y and z. The degrees turn in the order z, then x, then y: x tilts, y rolls, and z turns like a compass.

vec3 pos = [0, 0, 0];
vec3 target = [5, 5, 0];
rotation facing = [0, 0, 90];               -- a quarter turn around z

vec3 toTarget = target - pos;
rotation goal = Rotation:toward(toTarget);
facing = facing:lerp(goal, 0.1);            -- turn a tenth of the way
vec3 ahead = facing * [1, 0, 0];            -- the direction facing points
is ahead:angle(toTarget) < 5? then { print("in sight"); }
  • A rotation times a vec3 turns it; a rotation times a rotation turns by one and then the other; facing *= turn; turns it in place.
  • facing:degrees() gives its degrees as a vec3, facing:inverse() the turn back, facing:lerp(goal, t) part of the smooth turn to another.
  • Rotation:toward(dir) faces a direction, never rolling. Rotation:around(axis, degrees) turns around an axis: Rotation:around([0, 0, 1], 90) is [0, 0, 90].
  • Rotation with a capital is the object; rotation is the type.

vec2

A vec3 without z, for 2D games:

vec2 pos = [3.0, 4.5];
vec2 speed = [2, 0];
pos += speed * 0.5;
vec2 left = speed:rotated(90);           -- a quarter turn counter-clockwise
print(left, pos:distance([0, 0]));
  • The same arithmetic and methods as a vec3, plus rotated(degrees), and cross(b) gives a float: above 0 when b turns left from a.
  • pos3.xy is a vec3's x and y as a vec2, and pos:withZ(z) makes a vec3 from a vec2. A vec2 and a vec3 don't mix.

colour

Four numbers from 0 to 1: red, green, blue and how solid it is (a).

colour sky = [0.4, 0.7, 1.0];            -- solid
colour glass = [1, 1, 1, 0.5];           -- half see-through
colour warn = orange5;                   -- a colour word
colour moss = Colour:hex("#3a8f2a");     -- or "#3a8f2a80", with see-through
colour dusk = sky:lerp(warn, 0.5);
print(sky, dusk.r, moss:hex());
  • Colour words are the ones views use: white, black, gray1 to gray9, and red, orange, yellow, green, teal, blue, indigo, purple and pink, each with shades 1 (palest) to 9 (deepest). See Colours.
  • Parts: c.r, c.g, c.b and c.a, kept between 0 and 1. Written as numbers, a part outside 0 to 1 is a mistake (for 0 to 255, divide by 255).
  • Methods: c:fade(alpha), a:lerp(b, t) and c:hex(). There's no arithmetic on colours.
  • print and .text() show the hex text. Colour with a capital is the object; colour is the type.

Arrays, cMaps and maps

Arrays

int array scores = [10, 20, 30];

print(scores[0]);          -- counted from 0
print(#scores);            -- how many: 3
scores:inject(40);         -- adds to the end
scores:remove(0);          -- removes by position
scores[0] += 5;

string array names = [];
names:inject("Ada");

Arrays have tools for sorting, summing, picking and more: see Array tools.

cMaps: tables of rows

A cMap is a table whose rows are found by their key. The first column is always the key: you choose its name, and whether it's an int or a string.

cMap(int id, string itemName, int amount) bag = [
    [1, "Sword", 1],
    [2, "Apple", 5]
];

cMap(string name, int price, int stock) shop = [
    ["tea", 2, 10],
    ["cake", 5, 3]
];

print(shop["tea"].price);
shop["tea"].price = 3;
shop:inject(["bread", 3, 8]);
shop:remove("cake");
print(shop:has("cake"), #shop);
shop:sortBy(price);

loop (string name, int price, int stock in shop) {
    print(name, price, stock);
}
  • bag[1] is the row with key 1 (not the second row); shop["tea"] the row with key "tea".
  • A key can't be changed. To give a row a new key, remove it and add it again.
  • :sortBy(column) puts the rows in order (rows with the same value keep their order), and :reverse() turns them around.
  • Looping goes through the rows in the order they were added.

Keys Lust makes

A new row can leave its key out, and Lust makes one:

  • An int key counts up from the biggest key so far: bag:inject(["Map", 1]); gets 3.
  • A key-maker makes it instead: a method or hook that takes nothing and gives back a key, written after the key column like a starting value.
  • A string key with no key-maker has to be given every time.
method int rollId() {
    return Random[1000, 9999];
}

cMap(int id = rollId, string item, int amount) chest = [];
chest:inject(["Ruby", 1]);    -- gets a key from rollId

If the key-maker gives a key that's taken, Lust asks it again (and stops after 100 taken keys in a row). A key-maker goes where a cMap is made: on a variable or a field, not in a method's parameters.

Maps

int map prices = ["apple" 3, "seed" 1];

print(prices["apple"]);
prices["pear"] = 5;           -- adds or changes
print(prices:has("pear"));
prices:remove("seed");

loop (string fruit, int price in prices) {
    print(fruit, price);
}

Keys are text. A cMap with one column after its key does the same job, but maps are quicker to write for that.

States and memory

States describe what things are doing, and they own memory: what's made inside a state is let go when the state ends.

A state and its options

state GameState = [
    MainMenu,
    ActiveGame [
        Exploration,
        Combat
    ]
];

GameState now = GameState.MainMenu;
now is GameState.ActiveGame.Combat;      -- or: now = …;

is now == GameState.ActiveGame? then {
    print("playing");                     -- yes: Combat is inside ActiveGame
}
is now === GameState.ActiveGame? then {
    print("only ActiveGame itself");      -- no: === asks for that very option
}
  • Options can hold options of their own, as deep as you like.
  • A question about an option includes everything inside it; === asks for that very option.
  • loop (GameState s in GameState) { … } goes through every option.
  • Go through the options with check, which makes sure none is forgotten.

A thing's own state

A class or object can have a state of its own, written state is …; in its has. Inside its methods, state is …; changes it, and state reads it:

state Phase = [Calm, Battle];

class Guard {
    has {
        state is Phase.Calm;
    }

    method alarm() {
        state is Phase.Battle;
        is state == Phase.Battle? then { print("To arms!"); }
    }
}

Outside a class or object there's no state to change; use a variable.

Things made in a state end with it

Anything a thing with its own state makes with new in one of its methods belongs to the option it's in at that moment, and ends when it leaves that option. keep holds onto it:

state Phase = [Calm, Battle];

class Item {
    has {
        string name = "";
    }
}

class Hero {
    has {
        state is Phase.Calm;
        Item array bag = [];
    }

    method grab(string name) {
        Item sword = new Item { name = name };
        keep sword in bag;      -- without keep, the sword would end when Calm does
    }
}
  • keep thing in place; holds onto it and puts it in an array (at the end), a field or a variable. keep thing; holds onto it without putting it anywhere.
  • Using something that has ended stops the program, saying why: this was made during Battle.Melee, and ended with it.
  • Options inside options count separately: something made during Battle.Melee ends when the thing moves on to Battle.Ranged.
  • Starting values in has, and anything made by code outside a class's methods, belong to no state.
  • Lust catches the simple slips before running: storing something just made in a field or array without keep is a mistake.

Classes, objects and their kin

A class describes a kind of thing; new makes one. An object is one ready-made thing. Nodes open and close, and assemblies make things from recipes.

class, has and new

class Dog {
    has {
        string name = "Rex";
        int hp = 10;
    }

    method bark() {
        print(name + " says woof!");
    }
}

Dog pet = new Dog { name = "Bo" };
Dog other = new Dog;          -- every field at its starting value
pet:bark();
print(other.name, pet.hp);
pet.hp -= 3;
  • Fields are written like variables, all inside one has { } block.
  • new makes a thing. The braces set fields; anything not mentioned keeps its starting value. With nothing to set, leave the braces out: new Dog.
  • . reads a field, : calls a method: pet.hp, pet:bark().
  • Inside its own methods, a thing's fields and methods are used by name alone: name, bark().
  • Things are shared, not copied: Dog same = pet; is the same dog.

object: one ready-made thing

object Game {
    has {
        int score = 0;
    }

    method add(int points) {
        score += points;
    }
}

Game:add(10);
print(Game.score);

An object is used by its name, like a class you never need to make. Good for a game's score, settings or anything there's only one of.

like: building on another class

class Player {
    has {
        string name = "Hero";
        int hp = 20;
    }

    method greet() {
        print("I'm {name}.");
    }
}

class Wizard like Player {
    has {
        int mana = 50;
    }

    method greet() {
        print("I'm {name} the wizard, with {mana} mana.");
    }
}

Player hero = new Wizard { name = "Merlin" };
hero:greet();
is hero like Wizard? then {
    print("a wizard after all");
}
  • A Wizard fits anywhere a Player does, and its methods replace Player's of the same name.
  • is hero like Wizard? asks what something really is.

node: something that opens and closes

A node is like an object, but it opens and closes again and again: a room in a game, a level, a menu. Closing it ends everything it made.

class Item {
    has {
        string name = "";
    }
}

node Cave {
    has {
        Item chest = new Item { name = "chest" };
        int visits = 0;
    }

    method onOpen() {
        print("You enter the cave.");
    }

    method onClose() {
        print("You leave the cave.");
    }
}

Cave:open();
Cave.visits = Cave.visits + 1;
Cave:close();
print(Cave:isOpen());
  • A node starts closed. Cave:open(); starts it fresh with its starting values, then runs onOpen if it has one.
  • Cave:close(); runs onClose, then ends everything the node made. Using one afterwards says this was made in Cave, and ended when it closed. Use keep to hold onto something.
  • While it's closed, using its fields or methods says to open it first. Opening an open node, or closing a closed one, is an error.
  • A node can't be like a class. onOpen and onClose take nothing and give nothing back.

Methods and hooks

Methods

Everything callable is a method: inside a class or object, or on its own.

method int doubleIt(int value) {
    return value * 2;
}

method greet(string who) {
    print("Hello, " + who);
}

method string describe(string name, int hp) {
    is hp <= 0? then {
        return "{name} is down";
    }
    return "{name} has {hp} hp";
}

greet("Ada");
print(doubleIt(21), describe("Bo", 0));
  • The return type comes first, and is left out when nothing comes back.
  • return value; gives back a value and ends the method. A plain return; leaves early.
  • Parameters are typed: (int a, string b).
  • Methods can be used before the line they're written on.
  • A method can't see the variables at the top of the file. Pass the value in as a parameter, or keep it in an object's field, which every method can reach: users belongs to the top of the file, and methods can't see those. Pass it in, or keep it in an object.

Hooks: methods kept as values

hook is the type of a method kept in a variable, field, array or map. The names in a hook's type are the names its body uses.

method int doubleIt(int value) {
    return value * 2;
}

hook int(int n) triple = new hook {
    return n * 3;
};

hook int(int) f = doubleIt;            -- an existing method works too

print(triple(5), f(5));

class Shop {
    has {
        hook(string item, int price) onSell = nothing;
    }

    method sell(string item, int price) {
        is onSell !== nothing? then {
            onSell(item, price);
        }
    }
}

Shop shop = new Shop;
shop.onSell = new hook {
    print("Sold {item} for {price}");
};
shop:sell("bread", 3);
  • new hook { } is just the body. What it takes and gives back comes from where it's going.
  • A hook in a variable is called like a method on its own: triple(5). One kept in a field is called with : from outside (shop:onSell("bread", 3);), or by name inside the class.
  • A new hook can read the variables around it, as they were when it was made, but can't change them. To share changes, keep the value in an object's field: objects are shared, not copied.
  • Calling a hook that's nothing stops the program, so check first: is shop.onSell !== nothing?.

Counting

Three parts, split by ;: a new variable to count with, the check that keeps the loop going, and the change after each round.

string array names = ["Ada", "Bo", "Cy"];

loop (int i = 0; i < #names; i += 1) {
    print(i, names[i]);          -- each name with its place
}
loop (int i = 10; i > 0; i -= 2) {
    print(i);                    -- down, by twos
}
loop (int i = #names - 1; i >= 0; i -= 1) {
    print(names[i]);             -- backwards through an array
}
  • The counter belongs to its loop: it's gone after the }, so the next loop can use i again.
  • The check is asked before every round, so a check that's false at the start means no rounds.
  • The change still happens after skip;.

stop and skip

int array scores = [4, 0, 9, 12];

loop (int s in scores) {
    is s == 0? then { skip; }     -- on to the next round
    is s > 10? then { stop; }     -- out of the loop
    print(s);
}

stop; is other languages' break, and skip; their continue.

Everything in a file is private until it's passed.

  • fetch brings in classes, objects, states, assemblies and schemas; get brings in methods. Several at once go in [ ]: fetch "entities/player":[Player, Party];.

Projects and running one file

  • Only the file being run runs its code. The code at the bottom of a fetched file is left out, so any file can be run on its own to try it: lust run entities/player.lst from the project's folder, or lust run player.lst from inside entities.
  • Lust finds the project's folder (the nearest one up with a main.lst) either way.
  • Mistakes name the file they're in: entities/player.lst:12 ….
  • LustScript works the same way with .lsc files, and a LustScript program turns into one Lua file.

Saves and databases

Saves

object Farm {
    has {
        int crops = 0;
    }
}

int currentDay = 1;
save gameSession = [Farm, currentDay];

is saved gameSession? then {
    load gameSession;
}

currentDay += 1;
save gameSession;
  • A save lists what it holds once, at the top of the file: objects, and variables declared above it. Then save and load do the rest.
  • The file is gameSession.save, readable JSON, in the folder the program runs from (the program's own folder when it's double-clicked).
  • saved gameSession is true when there's a save to load.
  • Loading is strict: if the save doesn't fit the program, nothing changes and the error says why: gameSession's save doesn't fit this program, so nothing was loaded: it has no currentDay.
  • Hooks aren't saved, and nodes can't be: save what's in them. A save that holds variables can only be saved and loaded from the top of the file.

Databases

A database is a file of tables, kept by SQLite. Each table is written like a cMap and used like one:

database Shop in "shop.db" {
    cMap(string name, float price, int stock) items;
    cMap(int id, string who, string item) orders;
}

Shop.items:inject(["tea", 2.5, 10]);
Shop.items["tea"].stock = 9;            -- changes the database straight away
print(Shop.items["tea"].price);
print(#Shop.items);
  • The first column is the key. An int key counts up when a row leaves it out, and a removed row's key is never given out again. A string key has to be given.
  • Columns hold numbers, text, bools, state options, vectors, rotations and colours.
  • :inject, :has(key), :remove(key) and [key] work as on cMaps, and a row found with [key] reads and changes the database itself.
  • Programs with a database are built with Cargo; the first build on a computer takes a minute or two.

Queries

Queries pick rows. They're written in Lust, and Lust turns them into SQL:

database Shop in "shop.db" {
    cMap(string name, float price, int stock) items;
}

loop (string name, float price, int stock in Shop.items:where(price <= 3.0 && stock > 0)) {
    print(name);
}

cMap(string name, float price, int stock) cheapest = Shop.items:orderBy(price):first(3);
Shop.items:where(stock == 0):remove();
QueryGives
:where(condition)The rows where it's true; the columns are used by name
:orderBy(column)The rows in that column's order, smallest first
:reverse()The same rows the other way round
:first(n)Only the first n
:count(), or #How many
:remove()Removes the rows the query picked
  • Queries chain: Shop.items:where(stock > 0):orderBy(price):first(5).
  • Inside :where, columns work with maths, comparisons, &&, ||, not, #, :contains, :startsWith and :endsWith. Anything that doesn't use the columns is worked out first.
  • Vectors, rotations and colours are kept as text, so :where and :orderBy can't use them: loop through the rows and check each one instead.
  • Putting a query in a cMap variable copies its rows, so changing the cMap doesn't change the database.

Tweens: values that glide

A tween moves a value to a new one over some seconds, a little each moment, instead of jumping: a health bar draining, a door swinging open, the sky turning orange. Tweens work everywhere, not only in windows.

tween

object Hud {
    has {
        int hp = 100;
        vec3 pos = [0, 0, 0];
        colour sky = blue3;
    }

    method sunset() {
        tween hp to 0 over 0.5;
        tween pos to [10, 0, 0] over 2 [ease OutCubic];
        tween sky to orange5 over 1 [ease InOutSine] {
            print("sunset done");      -- runs when it ends
        }
    }
}

Hud:sunset();
wait 2;
print(Hud.hp, Hud.pos);
  • The shape: tween place to value over seconds;, then if you want them [ease Name] and a done block. With a done block there's no ; after the }.
  • What it moves: a field, or a variable at the top of the file, holding an int, float, vec2, vec3, colour or rotation. Not a method's own variable (it keeps going after the method ends), and not one part of a vector (tween the whole pos).
  • A new tween replaces the old on the same place, from where it is; the old done block never runs. over 0 sets it straight away.
  • tween, to and over are words only in a tween, so they can still be names.

Easing

With no [ease …] a tween moves at one speed, Linear. The others start slow (In…), end slow (Out…) or both (InOut…):

FamilyEases
SineInSine, OutSine, InOutSine: the gentlest
Quad, Cubic, Quart, QuintInQuad … InOutQuint: each a little sharper
ExpoVery slow, then very fast
CircLike a quarter circle
BackGoes a little past the end first
ElasticWobbles like a spring
BounceBounces like a dropped ball

Ease is a state whose options are the curves, so a variable can hold one (Ease chosen = Ease.OutBack;, then [ease chosen]), and an object: Ease:apply(Ease.OutBack, t) gives the curve's value for t from 0 to 1. The curves are the standard ones from easings.net.

When tweens move

  • In a window, each frame, on the same clock as every timers and animate.
  • In a plain program, during wait seconds;, in steps of 1/60 s. Without a wait, nothing moves, and tweens still running when the program ends just stop.
  • In a game engine, once a tick (see Lust in other programs).
  • A tween takes the same steps in lust run and a built program, so both end with the same numbers.

Web servers

A Lust program can be a server that answers web requests with JSON. Pages in the browser stay HTML, CSS and JavaScript.

schema: the shape of data coming in

schema NewUser {
    has {
        string name;
        int age = 0;
    }
}
  • A field with no value must be filled in; a field with a value is optional.
  • A schema only holds fields: no methods, no like. new NewUser { name = "Ada" } must fill in every field with no value.
  • When JSON is read into a schema, a missing field is an error that names it.

route: answering requests

schema NewUser {
    has {
        string name;
    }
}

class User {
    has {
        int id = 0;
        string name = "";
    }
}

object Users {
    has {
        User array all = [];
    }
}

method User getUser(int id) {
    loop (User u in Users.all) {
        is u.id == id? then { return u; }
    }
    Web:fail(404, "there's no user {id}.");
    return nothing;
}

method User createUser(NewUser body) {
    User u = new User { id = #Users.all + 1, name = body.name };
    Users.all:inject(u);
    return u;
}

route "/api" {
    get "/users/:id" => getUser;
    post "/users" => createUser;
}

print(Web:request("POST", "/api/users", "{\"name\": \"Ada\"}"));
print(Web:request("GET", "/api/users/1", ""));
  • get, post, put and delete are the kinds of request. The text after route goes in front of every path.
  • A value named like a :name in the path comes from the path; any other value comes from the body, read as JSON (usually a schema).
  • What the method gives back is the answer, as JSON, with status 200; a method that gives nothing back answers 204. Web:fail(404, "…"); answers with an error. A bad path value or body answers 400 by itself.
  • Web:serve(8080); answers requests on that port until the program is stopped. Web:request(…) tries a route without a network, for tests.

Asking other websites

string answer = Web:get("https://api.example.com/weather?city=Oslo");
Weather w = Json:read(answer);

Both give back the answer's text; turn JSON into Lust values with Json:read. If the site can't be reached or answers with an error, the program stops with what happened, so use try to carry on. Programs that ask websites are built with Cargo, like ones with databases.

LustScript and Lua

LustScript (.lsc)

LustScript is Lust turned into Lua, for running inside programs that already speak Lua: Garry's Mod, Aventail, Halberd, or any Lua 5.1, LuaJIT or Luau host. It's the same language with the same rules and checks; only the output differs.

  • lust run file.lsc runs it straight away; lust build file.lsc writes file.lua next to it; lust lua file.lsc shows the Lua.
  • Lua has no separate whole numbers, so int is checked strictly by Lust and becomes a plain number in Lua.
  • Databases, patterns, Files:list, the file boxes and the precise clock need lust run; inside other programs they say they aren't available.

Lust inside other programs

Lust can be one part of a bigger program, like a game engine written in Rust: the engine does the drawing, physics and sound, and Lust holds the game's own logic.

Native methods

class Entity {
    has {
        int id = 0;
    }

    method float x() native;
    method moveBy(float dx) native;
}

method float now() native;

pass Entity, now;
end

A method ending in native; has its body in the program Lust is part of. Lust still checks every call against it. Its body comes from the Rust program (built with --library), or from a Lua function in LUST_NATIVES (LustScript); run on its own, calling it stops with a message saying where its body lives.

Components and events

event Hit(entity by, float damage);

component Health {
    has {
        float hp = 10;
    }

    on Hit(entity by, float damage) {
        hp = hp - damage;
    }
}

component Gun {
    has {
        int ammo = 30;
        entity target = nothing;
    }

    method update(float dt) {
        send Hit(this, 6) to target;
    }
}

pass Health, Gun;
  • A component is a class whose fields the engine keeps and shows in its inspector, and whose update(float dt) it runs once a tick. Fields hold bool, int, float, string, a state, vec3, vec2, rotation, colour and entity.
  • this is the entity the component is on. The engine's abilities on entity are called bare inside a component: moveTo(position() + [1, 0, 0]).
  • event Name(…) says what an event carries; on Name(…) { } in a component handles it; send Name(…) to target; queues it with the engine.
  • A passed object is one for the whole game: the engine ticks its update and saves its fields.
  • Data files are ordinary .lst files holding only lock values of fixed values, which an engine reads without running anything.

Lust as a Rust library

lust build game.lst --library makes a game_library folder, a Rust library a Rust program uses with one line in its Cargo.toml, which Lust prints. game::start() runs the file's own start; each class the file passes is a Rust type with getters, setters and methods; native methods' bodies come from the program's game::Host. An engine can also use Lust's compiler itself (lust::check, lust::to_lua) to check a game and run it as Lua while it plays. Section 21 of LUST.md has every detail.
