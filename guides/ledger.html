Ledger User Guide

Ledger is a code editor for Rust, C#, Godot, web projects, Lua and Lust. This guide walks through every part of it, with the keys for each. Everything in Ledger can be done from the keyboard.

Use the search box at the top (press / or Ctrl+K) to find anything, or pick a chapter on the left. Every heading has its own link: point at it and click the hash sign beside it to copy where it is.

Ledger has no AI in it, and never will. No assistant, no chat panel, no generated code, nothing sent off to a model. What's in your files is what you wrote.

To open this guide again, press Ctrl+Shift+P and type Docs. The Lust language guide opens the same way.

The short version

  1. Press Ctrl+O to open a project folder, or run New project from the command list (Ctrl+Shift+P).
  2. If Ledger asks whether you trust the folder, say yes for your own code. See Trusting a folder.
  3. Open files with Ctrl+E (type part of a name), and press F5 to run. Type into the Input box under the output when the program asks for something.
  4. Mistakes show as squiggles and in Problems; F8 goes to the next one. F12 goes to a definition, Shift+Alt+F12 follows everywhere something is used.
  5. Ctrl+Shift+P lists every command with its key. Ctrl+P opens Settings.

Getting started

Installing and updates

  • The installer (Ledger_…_x64-setup.exe) installs Ledger for you alone, with no administrator rights, and adds a Start menu entry, the ledger command and Open with Ledger in File Explorer's right-click menu. It makes .lst, .lsc, .lql and .lust files open in Ledger with their own icons.
  • Ledger-portable.exe runs from anywhere and needs nothing else on Windows 11.
  • Updates: when Ledger starts, a small window checks for a new version first. Update now downloads, installs and starts the new Ledger; Later (or Esc) opens Ledger as it is. The check gives up after 8 seconds, so being offline never holds Ledger back. Settings › Updates turns it off; Ledger then checks once it's open and shows Restart to update. Updates are signed, and an unsigned one is refused.

Opening a folder

Each window has one folder open. Press Ctrl+O, or pick a recent folder on the start page. Open a project folder (with Cargo.toml, a .sln or .csproj, project.godot, package.json or main.lst), or a folder that holds several projects, like a course folder with one project per lesson.

  • Run, Build and Test always use the project of the file you have open. Its name shows at the left of the status bar.
  • Ctrl+Shift+N opens another window (or Ctrl+Enter on a recent folder), each with its own program, language servers, debugger and terminals. Ctrl+Shift+W closes a window.
  • From a terminal: Ledger.exe C:\Games\MyGame --goto C:\Games\MyGame\Player.cs:42.

Trusting a folder (restricted mode)

Opening a downloaded project shouldn't run its code. The first time Ledger opens a folder with a project or a Git repository in it, it asks whether you trust the code. Until you do, the folder is in restricted mode, shown as Restricted in the status bar (click it to trust the folder).

  • You can read, edit, search, format and commit as usual. HTML, CSS, JSON and TypeScript help work, with the computer's own TypeScript.
  • Run, Build, Test and Debug ask for trust first, since they run the project's code.
  • Rust, C# and Lua analysis wait, since their servers run the project's build scripts and plugins.
  • Git runs with the repository's hooks switched off.
  • Lust checking works in restricted mode, since lust check only reads the code.
  • Projects you make in Ledger are trusted. Trust this folder, or go back to restricted mode in the command list changes your answer.

Making a new project

Run New project from the command list. With a folder open, Ledger asks whether the project goes inside it (a course folder, say) or somewhere else.

Starting a Git repository for a project writes a .gitignore that fits what's in it (target, bin/obj, node_modules and so on).

The window at a glance

A side bar on the left, open files as tabs, the editor, a panel at the bottom for output, problems and terminals, and a thin status bar along the bottom (or the top).

The command list

Ctrl+Shift+P (or F1) lists every command with its shortcut. Type a few letters of what you want; commands also answer to other words for the same thing ("usages" finds Red Thread, "args" finds the run options). Every shortcut can be changed in Settings › Keyboard shortcuts.

In dialogs, the arrows move and Enter picks; in short choice dialogs the number keys pick directly.

Ctrl+B shows or hides it. F6 and Shift+F6 move between the explorer, editor, panel and status bar; Esc goes back to the editor.

The panel

The bottom panel holds Output (Ctrl+Shift+U), Problems (Ctrl+Shift+M), Terminal (Ctrl+`), Tests, TODO and the debug console. Ctrl+J shows or hides it.

The status bar

  • At the left: the project of the open file, the Git branch (click to switch), and Restricted when the folder isn't trusted.
  • The language servers: one with a warning or error shows it in colour; click it to read why. A missing server is red, with a button to its setting.
  • Line and column, indentation (click to change it for this file), the file's encoding, and Go Live for web folders.
  • For .NET: the startup project, Debug or Release, the framework, the launch profile and dotnet watch.
  • While audio plays, what's playing (click to go back to it).

Settings

Ctrl+P opens Settings, with a search box at the top. Among them:

  • Appearance: light, dark or matching Windows; quiet code colours (a few) or colourful ones; fonts and sizes; the status bar along the bottom or the top; file icons.
  • Editor and Editing: tab size, wrapping, format on save, auto save, the minimap, sticky scroll, type hints, whether Tab takes the highlighted suggestion, your snippets, and the explorer following the open file.
  • Markdown: whether Markdown files open as the editor, the preview, or both side by side.
  • Web: the browser (Windows default, Chrome, Edge, Firefox, Brave, or another program) and Live Server's port.
  • Languages, C# and .NET, Lust, Godot, Debugging: one-click installs and the paths to your own tools.
  • Keyboard shortcuts: change any command's keys.
  • Git, Updates, Windows: blame, update checks, and Open with Ledger in File Explorer.

The editor's own keys (Ctrl+Z, Ctrl+D, Ctrl+/ and the like) are fixed. Ctrl++, Ctrl+- and Ctrl+0 change the editor's text size.

Files

The explorer

  • Keys: the arrows move, Right and Left open and close folders, Enter opens, Space (or a click) shows the file in a preview tab and stays in the explorer, F2 renames, Delete moves to the Recycle Bin, Ctrl+X/C/V move and copy files, Shift+F10 opens the menu, and typing jumps to a name.
  • New files and folders: Ctrl+N and Ctrl+Alt+N. Dragging files from File Explorer onto a folder copies them in.
  • Ctrl+Shift+R shows the current file in the explorer. Changed files are coloured by Git, and folders with problems show how many.
  • Folder icons follow what's inside: a folder of only audio files gets an audio folder icon in the audio colour, one of videos a video icon, and the same for pictures and fonts.

Add to .gitignore

Right-click any file or folder in the explorer and choose Add to .gitignore. For a file there's also Add all *.ext files to .gitignore, for every file of that kind. Ledger adds the line to the project's .gitignore (making one if there isn't one), and the file drops out of Source control.

Tabs

  • Clicking through files in the explorer reuses one preview tab (in italics) until you edit, save or pin it. Diffs, the CSV table and the hex view open the same way.
  • Ctrl+Tab and Ctrl+PageDown/PageUp go to the next and previous tab; Ctrl+1 to Ctrl+9 to a tab (9 is the last).
  • Ctrl+W closes a tab, Ctrl+Shift+T reopens it.
  • Right-click a tab to pin it, copy its path, show it in the explorer, open it to the side, or close the tabs to its right, the saved ones or all of them.
  • When there are more tabs than fit, the edges fade and a list of every open tab sits at the right end.
  • Ctrl+\ splits the editor (again: switch side); Ctrl+Shift+\ closes the split.

Music, video, pictures and other files

  • Audio (MP3, WAV, OGG, Opus, FLAC, M4A, AAC) opens in its own tab with a waveform to click or drag through. It keeps playing while you work in other tabs, and the status bar shows what's playing. Space plays and pauses, ← and → skip 5 seconds, L loops.
  • Video (MP4, WebM, MOV, OGV, and MKV where Windows can play it) plays in a tab too.
  • Fonts (TTF, OTF, WOFF, WOFF2) show as sample text.
  • Pictures (PNG, JPEG, GIF, WebP, SVG, AVIF, BMP, ICO) open in a viewer with zoom, a checkerboard behind see-through parts, and a pixel-art mode; SVGs can be edited as code.
  • Documents and archives (PDF, Word, Excel, PowerPoint, ZIP and the like) show a card saying what they are, with a button to open them in the app Windows uses.
  • Databases (.db, .sqlite) open in a tab with tables, sorting, filters, a SQL tab and editing with review. Right-click in the explorer for a new SQLite database.
  • CSV and TSV files colour each column; Ctrl+Shift+V shows them as a table with sorting and a filter.
  • Binary files open in a hex view; right-click any file for Open as hex.
  • Files too big to edit (over 8 MB: logs, data dumps) can be read, their first or last 4 MB, read-only; Big file: show the end and show the start switch.

Markdown preview

  • Ctrl+Shift+V shows the preview instead of the source, so you don't read the same file twice; the same keys go back to the source. Your place is kept across the switch.
  • Ctrl+Alt+V shows the preview beside the source, updating as you type.
  • Settings › Markdown picks how a Markdown file opens the first time: in the editor, as the preview, or with both.

Local history and encodings

  • Every save keeps a copy (the last 50 per file, in Ledger's own folder, not your project), plus the file as it was before you started editing. Local history: this file's saved versions (or right-click a file) shows any of them next to the file now, with Restore this version. It works in folders without Git.
  • Encodings: UTF-8, UTF-16 and old Windows-1252 files open and save in the encoding they came in, shown in the status bar; Convert this file to UTF-8 switches. Files with a byte-order mark or Windows line endings keep them.
  • A file you're editing that changes on disk gets a warning.

Editing

Completion and info

  • Suggestions show as you type; Ctrl+Space asks for them. Tab or Enter takes the highlighted one and fills in the word. (Settings › Editing can make Tab always indent instead.)
  • When a language's server isn't running, Ledger still suggests the words already in the file.
  • Ctrl+K shows info at the cursor (type, docs, errors); Ctrl+Shift+Space shows parameter hints. Ctrl+. offers quick fixes and refactors.
  • Type hints (like count: usize) show in grey and aren't part of your file. Toggle type hints turns them off.

Selecting and multiple cursors

  • Ctrl+L selects the line; Ctrl+D adds the next match of the selection; Ctrl+Shift+L selects every match.
  • Ctrl+Alt+Up/Down add a cursor above or below.
  • Ctrl+Shift+Enter starts a new line above; Ctrl+/ comments lines out; Alt+Z wraps long lines.
  • The command list sorts, de-duplicates and changes the case of lines.

Find and replace in the file

Ctrl+F finds, Ctrl+H replaces (Tab goes from the find box to the replace box). Match case, whole word and regular expressions are buttons on the bar, which says "3 of 20". Ctrl+G goes to a line.

Search in files

Ctrl+Shift+F searches the whole folder, with match case, whole word, regular expressions, and files to include and leave out. Ctrl+Shift+H replaces in files, with a preview first; replace one match or one file from its hover buttons, or leave it out. Unsaved changes in open files are searched as they are.

Formatting and indentation

  • Shift+Alt+F formats the file (or on save, in Settings). Web files use the project's own Prettier, or Ledger's built-in one. Rust uses rustfmt, C# dotnet format.
  • Each file is indented the way it already is (2 spaces, 4, tabs), shown in the status bar; click it to change it. A C# project's .editorconfig is followed.

Snippets and Emmet

  • Snippets come in the suggestion list (prop, ctor, foreach in C#; a snippet for each Lust piece, and more). Tab moves to the next place to fill in. Add your own per language in Settings › Editing › Edit snippets.
  • Emmet in HTML, JSX and CSS: type ul>li.item*3, div.card>h2+p, ! for a whole page, or m10, df in CSS, then Tab. The suggestion list shows what it becomes.

Colours

Every colour in code (#hex, rgb(), hsl(), Godot's Color(), Lust's colour words) gets a small swatch. Click it for a colour wheel or hexagon grid, an alpha slider, Hex and RGB fields, the colours already in the file and your saved colours; the code changes as you pick, written the way it was. Pick a colour puts a new one at the cursor.

Bookmarks, minimap, Zen and more

  • Bookmarks: Ctrl+Alt+K marks a line, Ctrl+Alt+L and Ctrl+Alt+J go to the next and previous; Bookmarks: list shows them all. They're kept for next time.
  • The minimap at the right edge is a small picture of the file; click to jump, drag to scroll. Errors and Git changes show on it.
  • The overview ruler marks errors, search matches, Git changes and bookmarks along the scrollbar.
  • Zen mode (Ctrl+Alt+Z) hides everything but the editor and goes full screen.
  • TODO panel: every TODO, FIXME, HACK, XXX and BUG comment in the folder.
  • Folding, coloured bracket pairs, indent guides, and sticky scroll (the line opening the current function stays pinned at the top).

Getting around

Go to file

Ctrl+E opens any file by typing part of its name, recent files first. Type @ or # to search symbols instead, and file:line to jump to a line.

Definitions and references

  • F12 (or Ctrl+click) goes to where something is defined; Shift+F12 lists every use of it.
  • F2 renames it everywhere.
  • Alt+Left and Alt+Right go back and forward through your jumps.
  • C# adds go to implementation (Ctrl+F12), type definition, callers (Shift+Alt+H), and base and derived types.

Red Thread: follow where it's used

Red Thread shows everywhere a piece of code is used, and everywhere those places are used, as columns side by side. It's for exploring: open it, follow the thread, close it.

  1. Put the cursor on anything (a variable, a function, a class, a method) and press Shift+Alt+F12.
  2. The first column is its definition and every place that uses it, grouped by file, each with the function or class it sits in.
  3. Pick one, and a column slides in to the right: that function's code with the use marked, and everywhere it is used. Keep pulling the thread; a red line joins each pick to where it leads.
  4. Double-click a place (or Ctrl+Enter) to open it in the editor.

Nothing is saved: close the tab and the thread is gone. The language servers answer, so a use is a real use; for a language with no server (Lust, say), the uses are matches of the name, and say so.

Outline and symbols

Ctrl+Shift+O lists the open file's classes, functions and the rest (a Markdown file's headings). Ctrl+Alt+O searches symbols across the whole folder.

Running, building and testing

Run and stop

  • F5 runs the project of the open file: cargo run, dotnet run, the dev or start script, node, lua, lust run, or Godot's Play. Running saves all open files first.
  • Shift+F5 stops it, endless loops and the programs it started included. While a program runs, the Stop button shows how long it has been going.
  • Ctrl+Shift+B builds, Ctrl+Alt+T runs the tests, Ctrl+Alt+C checks (Rust, Lust). Scripts… runs any package.json script.
  • Only one thing runs at a time. Starting another while one runs asks first, with Keep it running as the default.
  • Links in the output (file:line, and localhost:5173 with its port) are clickable.

Typing to your program

While your program runs, an Input box appears under the output. Type a line and press Enter, and it reaches read_line, Console.ReadLine, Lust's ask and the like. Ctrl+I jumps to it; End input closes the program's input. Programs run without a console window.

Arguments and input

Run and Debug: arguments and input for the program… (in the command list) sets the arguments a project gets when you Run or Debug it, like --verbose data.txt "two words", and the lines a debugged program reads (a program started by the debugger can't be typed to). They're kept per project.

Problems and output

  • Errors and warnings from the language servers and from builds (cargo, dotnet, lust check) go to Problems (Ctrl+Shift+M) and into the editor as squiggles.
  • F8 and Shift+F8 go to the next and previous problem, with its message.
  • The output keeps up with the program while you're at the bottom; scroll up to read and it stays put, and scrolling back down follows again. Output and error lines come in the order the program printed them.
  • A build that finishes but didn't quite work (a package restore that failed, say) shows a warning instead of a green Finished.

The Tests panel

  • Finds Rust, C# and Lust tests. Run all of them, the failed ones, a file, or one test; the output shows live with a Stop button.
  • Each failure shows its message and line, and results are marked next to each test in the editor. ▶ Run test and Debug sit above each Rust and C# test and above main.
  • Ctrl+Shift+F10 and Ctrl+Shift+F9 run or debug the test at the cursor.
  • Filter by name or category (Category=Fast). Coverage runs the C# tests with coverlet and marks the lines that ran. Tests: create a test for this file gets you started.

Debugging

  • F9 sets a breakpoint on the line; Shift+F9 starts debugging; F5 continues; F10, F11 and Shift+F11 step over, into and out; Ctrl+Shift+F5 restarts; Pause pauses; Shift+F5 stops.
  • The Debug view (Ctrl+Shift+D) shows variables, watches and the call stack, with a debug console in the panel.
  • Debug: pause on exceptions picks when to stop: when nothing catches them (the default, and on Rust panics), whenever one is thrown, or never.
  • Debug: attach to a running program picks a process.
  • Rust uses codelldb, C# and Godot use netcoredbg; Ledger offers to download them the first time you need them.
  • A debugged program can't be typed to: set its input in Arguments and input.

Languages

Settings › Languages installs Node.js, Lua, Rust, the .NET SDK, Git, Lust and the language servers with one click, and shows which tools it found.

Rust

Run, check, test and Clippy with cargo; live errors, completions, hover docs, go to definition, rename, quick fixes and rustfmt through rust-analyzer (rustup component add rust-analyzer rust-src, or the button in Settings). Errors from cargo go to Problems even without rust-analyzer. In Cargo.toml, the newest version of each package shows at the end of its line; click it to update.

C# and .NET

  • Build, run and test with dotnet, and the editor features through csharp-ls or Microsoft's Roslyn (Settings › C# and .NET).
  • The Solution view lists the projects with their packages, references, frameworks and launch profiles. Right-click a project to run, build, test, clean or publish it, set it as the startup project, manage its NuGet packages or add a reference; + makes a new project from any template.
  • NuGet: a page per project to search, install, update and remove packages, and list known vulnerabilities.
  • ASP.NET Core and EF Core: user secrets, the HTTPS development certificate, .http files with ▶ Send request, EF migrations, and C#: publish….
  • Go to definition reaches into NuGet packages and the framework, through Source Link or decompiled, read-only.

Web projects and Go Live

  • HTML, CSS (SCSS, Less), JavaScript and TypeScript with React: completions, errors and go to definition through the TypeScript, HTML, CSS and JSON servers. Tailwind classes complete with colour swatches.
  • package.json projects run their dev/start script with F5; Build, Test and Lint use their scripts. A single .js or .ts file runs with Node. ESLint's problems link to the right file and line.
  • Go Live in the status bar serves the folder and reloads the browser on save (CSS changes swap in without a reload). Settings › Web picks the browser and port.

Lua

Highlighting, Run with F5, and the Lua language server, with a Lua version setting.

Lust

  • .lst programs and .lsc LustScript files get highlighting, completions, snippets and their own icons: Lt, Ls and Lq for LustQL.
  • Views: pieces in the classes' blue and style words muted. Inside a piece's [ ], completion offers only the style words that fit it, colours after color, background and border, and your named styles. Colours show a square of their real colour, and hovering a style word or piece explains it with an example.
  • Run (F5) runs the open file with lust run from the project's folder, with the Input box for ask; Check and Build use lust check and lust build.
  • Every save checks the file quietly, and its mistakes show up in Problems and as squiggles. For a name Lust doesn't know, Ctrl+. offers Did you mean ….
  • F12, Shift+F12, F2 and hovering work by name across the folder's Lust files, open tabs included, saved or not. Hovering a name shows where it's declared.
  • Lust: show the Lua this file turns into and show the Rust open in a read-only tab.
  • Ledger needs lust.exe: Install Lust in Settings › Lust builds it from the Lust repo with Rust, or set the path to one you have.

Everything about the language itself is in the Lust language guide.

Godot

  1. In Settings › Godot, pick your Godot .exe (the .NET build for C# projects). That's what Play uses.
  2. The same section shows the values to paste into Godot's Editor › Editor Settings, with Copy buttons: Dotnet › Editor for C# scripts, and Text Editor › External for GDScript.
  3. Double-click a script in Godot, and it opens in Ledger at the right line.

F5 builds the C# project and starts the game with its output in the panel; Ctrl+F5 plays the open scene. Shaders (.gdshader) get highlighting and completion.

Git

  • Source control (Ctrl+Shift+G) stages, commits, pulls and pushes. Hover a changed file for open, discard and stage buttons. Commit all asks before adding files Git doesn't track yet.
  • Changed lines are marked by the line numbers; Alt+F5 and Shift+Alt+F5 go to the next and previous change. A side-by-side diff shows what changed.
  • Branches: click the branch in the status bar to switch, make, merge or delete one. If switching would lose changes, Ledger offers to stash them first.
  • Stashes: put changes aside and pop, apply, look at or drop them.
  • History lists the branch's commits; click one to see what it changed.
  • Blame: the cursor's line shows who last changed it and when, faintly at its end; Ctrl+click it for that commit.
  • Merge conflicts get Keep yours, Keep theirs, Keep both and Compare above each one; Alt+F7 goes to the next.
  • Starting a repository writes a .gitignore that fits the folder, and Add to .gitignore is a right-click away.

The terminal and the ledger command

  • Ctrl+` shows a PowerShell terminal in the panel, Ctrl+T opens a new one.
  • In a terminal, Ctrl+letter keys go to the shell, except Ctrl+P, T, J and B. F6 or Ctrl+` gets you out.

Ledger's terminal has a ledger command; ledger help lists everything.

Troubleshooting

  • A language server shows a warning or error in the status bar: click it to read why. A missing one is red, with a button to the setting for it; Settings › Languages installs it.
  • Run asks for trust: the folder is in restricted mode. Click Restricted in the status bar if it's your own code.
  • A debugged program waits for input: it can't be typed to; set its input under Arguments and input, or use Run.
  • The browser doesn't open for Go Live: check Settings › Web's browser, or pick Windows default.
  • Lust isn't found: Settings › Lust › Install Lust, or set the path to your lust.exe. Building Lust programs needs Rust too.
  • Deleting from the explorer moves files to the Recycle Bin, so they can come back.
  • Lost a change? Local history keeps the last 50 saves of every file.
